# 開発セッションに渡すマスタープロンプト（/goal 用）

開発セッション「魔法FPSゲーム開発」で、以下をまとめて貼る。

```
/goal game/ に、ブラウザで遊べる「魔法使いの4vs4チームデスマッチFPS」を完成させる。完了条件:
(1) npm run build が通る
(2) node tools/simmatch.mjs でボット同士のフルマッチが最後まで進み、先取25キルかタイムアップで決着し、ページエラーが0
(3) node tools/screenshots.mjs のスクショを自分で見て、タイトル／あそびかた／ヒーロー選択／戦闘／スコープ／死亡／リザルトの各画面に、崩れや見にくい要素がない
(4) 音担当セッション @音楽生成 から、BGMと効果音の納品完了の返信を受け取り、manifest.json 経由でゲームに反映されている
```

続けて、アイデアを送る（作者の言う「ゲームの根幹になるアイデアだけ」に相当）:

```
ゲームの根幹アイデア:
- 右手の形が、そのまま銃になる魔法使いたちの撃ち合い。右手のジェスチャー（指鉄砲など）が武器、左手で魔法を唱える。
- 手遊び的な要素を中心に。両手がふさがる代わりに強力なジェスチャー（スナイパーライフル枠を含む）を入れて、構えている間は魔法が使えないトレードオフにする。
- 4vs4のチームデスマッチ。相手と味方はボット（強さを選べる）。アタッカー／タンク／ヒーラーのヒーローを選ぶ。
- 舞台は夜のネオン東京×神社。ポップでコミカル、日本語UI。

進め方:
- 技術は Vite + Three.js。外部3Dアセットは使わず、形状もテクスチャも全部コードで作る。ブルームで光らせる。
- 自分で起動して遊び、スクショを見て直す、を完了条件を満たすまで繰り返すこと。人間への確認は不要。
- 音は自分で作らず、必要な BGM／効果音の一覧を game/tools/audio/cues.json に書いて @音楽生成 に発注すること。納品までは Web Audio の合成音で仮置きする。
- 録画機能（F9でMP4保存）を付けて、SNSに投稿できるようにする。
```

ポイント: 仕様を細かく書きすぎない。完了条件（検証方法）を具体的に書き、アイデアは短く書く。作者の実例でも、👌をスコープにする発想はモデル側から出ている。
