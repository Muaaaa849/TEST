# Opus 5.5「魔法4vs4 FPS」制作手法の徹底検証と再現メソッド

対象ポスト: https://x.com/doerstokyo342/status/2102691983777280093 （こば@AIBridge Lab、2026-09-23）

> 1発だしでこのレベル！ Claude Opus 5.5にゲームの根幹になるアイデアだけを投げて4時間ほど放置したら本格的な4vs4のチーム戦が可能なFPSゲームが完成しました！
> 音楽はLyria 3.5、効果音はElevenlabsの専門家セッションへ自動で発注して作ってくれました

---

## 1. 結論（先に要点）

このゲームは **「Claude Code の長時間自走セッション（開発担当）」＋「音生成専用にカスタマイズした別の Claude Code セッション（音担当）」** の2セッション構成で作られています。開発セッションが音担当セッションへ **セッション間メッセージで自動発注** し、音担当セッションが **Lyria 3.5（Gemini API）で BGM**、**ElevenLabs で効果音**を生成しました。ゲーム本体は外部アセットを使わず、**ブラウザ上の Three.js 系 3D（プリミティブ形状＋キャンバステクスチャ＋ブルーム）** で全部コード生成されたものと判断できます。

この構成を本リポジトリで実際に再現し、**動画と画面単位で同等の構成・操作・ルール・見た目を持つゲーム（`game/`）が動くことを確認**しました（§5）。

## 3. 動画（173秒・1920x868）のフレーム解析でわかった仕様

動画は fxtwitter API 経由で取得しました（cobalt.tools の API は Turnstile の JWT が必要で、ヘッドレスでは使えません。同じ twimg の MP4 を直接取得）。4秒ごとのフレームと主要画面を確認しました。

- **プラットフォーム**: ブラウザ。マウスカーソルが見える。**F9「録画 開始/停止（MP4で保存・シェア）」** は `canvas.captureStream`＋`MediaRecorder` の典型実装。
- **対戦形式**: 4v4 チームデスマッチ、先取25キル／6:00、リスポーン4秒。相手は **ボット**（「ボットの強さ かんたん/ふつう/むずかしい」）。オンライン対戦ではない。
- **ヒーロー3種**: TRIGGER（アタッカー 100/150/7.4）、GAUNTLET（タンク 220/80/6.4）、MUDRA（ヒーラー 140/110/7）。
- **右手ジェスチャー＝武器**: フィンガーガン（セミオート）、ダブルタップ✌（散弾）、ホーンズライフル🤘（フルオート）、トリニティバースト🤟（3点）、スコープサイン👌（両手・狙撃）、シールバラージ🙏（両手・フルオート）。
- **左手＝魔法 Q/E/F**（即時型と「長押しで照準→離して発動」型）: フェイズステップ、ヴェール、ファイアボール、ミラーウォード、ヘックスマイン、エンバーウェイブ、癒しの泉、スネアルーン、ピュリファイウェイブ。
- **両手ルール**: 両手ジェスチャー中は魔法がロック（HUDに🔒）。リロード＝「指先をフーッ」。
- **演出**: ネオンの夜の東京×神社（鳥居・千本鳥居・桜・提灯・パチンコ看板・タクシー）、ブルーム、コミック擬音（BANG!/ZAP!/HEADSHOT KO!）、「やられた！ YOU GOT HEXED」、ダブルキル表示、キルフィード、MVP・個人成績つきリザルト。
- **アセット**: 形状はすべて箱・円柱・二十面体などのプリミティブで、外部 3D モデルの痕跡はない（手のモデルもカプセルの組み合わせ）。**全部手続き的に生成されたもの**と判断できる。

## 4. 推定ワークフロー（確度つき）

```
[あなた] ──アイデア（数行）──▶ セッションA「魔法FPSゲーム開発」 (Opus 5.5, /goal 等で長時間自走)
                                   │  Three.js/Vite でゲーム実装 → ブラウザで起動・スクショ確認 → 修正… を反復
                                   │  必要な音をキューシートにして
                                   └─SendMessage──▶ セッションB「音楽生成」(音生成専用に CLAUDE.md/システムプロンプトをカスタマイズ)
                                                      ├─ Lyria 3.5 (Gemini API) → BGM mp3
                                                      └─ ElevenLabs (MCP または API) → SFX mp3
                                   ◀──完了通知(SendMessage / notify_when_idle)── ファイルを所定フォルダへ配置
```

| 要素 | 判断 | 確度 |
|---|---|---|
| 2つの Claude Code セッションを1グループにまとめて運用 | スクショで確定 | 確定 |
| セッション間の自動発注 = **Cross-session messaging（`ListAgents`/`SendMessage`、v2.1.224〜）** | 「自動連携」「自動で発注」と、機能の時期（2026-08）が一致 | 高 |
| サイドバーのグループ表示 = Claude Code アプリのセッショングループ／2026-09-17 刷新の **Projects**（coordinator＋threads） | UI の形が一致。どちらかは断定できない | 中 |
| 4時間の無人稼働 = **`/goal`**（完了条件を満たすまで自走）または長い単一ターン＋サブエージェント | Opus 5.5 は長時間タスクとサブエージェントへの割り振りが得意とされる | 中〜高 |
| ElevenLabs = 公式 **ElevenLabs MCP**（ホスト型コネクタ）または REST API | Opus 5.5×ElevenLabs MCP の公式告知あり（2026-09-24）。どちらかは不明 | 中 |
| Lyria 3.5 = **Gemini API `lyria-3.5:generateContent`**（2026-09-04 公開、1曲 $0.08） | API は公開済み。Lyria の公式 MCP は見当たらないので、スクリプトから呼んだと推定 | 高 |
| 技術スタック = ブラウザ＋Three.js（WebGL）＋Web Audio | 画面・F9 録画・プリミティブ形状・ブルームから | 高 |

「1発だし」は **人間の指示が1回だけ** という意味で、Claude は内部で数百回の「実装→起動→確認→修正」を回しています。品質の決め手は、プロンプトの長さではなく **自分で遊んで確かめるループ（スクショ・自動対戦）を持たせたこと** です。ここは本リポジトリの再現作業でも同じでした（§5）。

## 5. 実証：このリポジトリで同じ手法を使って再現した結果

`game/` は、上の手法の開発セッション側（アイデア → 自律実装 → ヘッドレスブラウザで自己検証 → 修正）をこのセッションで実行した成果物です。

- **中身**: Vite＋Three.js、外部アセットゼロ。4v4 ボット戦、ヒーロー3種、ジェスチャー6種（両手ルールつき）、魔法9種、A* ナビのボット AI（難易度3段階・ヒーラーは味方を撃って回復）、ヘッドショット、アシスト、マルチキル、キルフィード、Tab スコアボード、リザルト（MVP・命中率ほか）、F9 録画（MP4/WebM）、あそびかた／ヒーロー選択画面。
- **音**: 全音を Web Audio で合成してあり、`public/audio/manifest.json` に生成ファイルを置くと差し替わる（音担当セッションとの受け渡し口）。生成ファイルによる差し替えが実際に効くことを確認済み。
- **自己検証の結果**（`tools/simmatch.mjs`、加速シミュレーションでフルマッチ）:

- **見た目の比較**（左が元動画、右が本ビルド）: `docs/img/compare_video_vs_build.jpg`、ジェスチャーの手の比較: `docs/img/gestures.jpg`

**差分（正直な評価）**: 画面の構成・ルール・操作・世界観は同等です。元動画のほうが上なのは磨き込みの細部で、スコープを囲む巨大な手のイラスト、ワールド空間の擬音スプライト、紙吹雪、看板の小物（魚・キツネ）などがあります。これは元作品が約4時間ループを回した分の差で、下の手順どおり `/goal` の完了条件に「元動画と比べた改善点リストが空になるまで」を入れれば、同じ方向に詰められます。また、この環境には API キーがないため、Lyria/ElevenLabs は実際には呼んでいません。呼び出しコードは公式ドキュメントの仕様どおりに実装済みです。

## 6. 再現手順（これで同品質に到達できる）

### 前提
- Claude Code v2.1.224 以上（クロスセッションメッセージ。同じマシン上の2セッションなら追加設定は不要）、モデルは Opus 5.5（`/model`）
- `GEMINI_API_KEY`（Lyria 3.5 は無料枠なし）、`ELEVENLABS_API_KEY` または ElevenLabs コネクタ（MCP）
- Node.js 20 以上、Playwright＋Chromium（Claude が自分で起動してスクショを確認するため。**ここが最重要**）
- 課金対策: 両サービスの管理画面で利用上限を設定しておく

### 手順
1. リポジトリを用意し、`CLAUDE.md`（開発規約と「必ず自分で起動して確認する」ループ）を置く → 本リポジトリの `CLAUDE.md`
2. **音担当セッション**を起動する（ターミナル1）
   ```bash
   cd <repo> && claude --name 音楽生成 --append-system-prompt "$(cat .claude/audio-session.md)"
   ```
   ElevenLabs MCP を使う場合: `claude mcp add` で公式 ElevenLabs MCP を追加するか、claude.ai のコネクタを有効にする。
3. **開発セッション**を起動する（ターミナル2）
   ```bash
   cd <repo> && claude --name 魔法FPSゲーム開発
   ```
4. 開発セッションで `/goal` を使い、アイデアと完了条件を渡す → `prompts/master_prompt.md` をそのまま貼る
5. 放置する（目安は数時間）。開発セッションは、必要な音を `game/tools/audio/cues.json` にまとめて `@音楽生成` へ発注し、音担当セッションは `node game/tools/audio/generate.mjs` で生成して `manifest.json` を更新し、完了を返信する
6. 仕上げ: `npm run dev` で遊んで、気になる点を1〜2行で追加指示する（例: スコープに手のフレームを付ける、擬音をワールドに出す）

### なぜこれで同品質になると言えるか
- 動画の要素を全部分解し、それぞれに実装手段が存在すること（§3・§5）と、実際に同じ構造のゲームが一度で動き、フルマッチが決着まで回ることを確認した
- 残る差は「反復回数」だけで、それは `/goal` の完了条件とスクショ比較ループで機械的に詰められる
- 音の自動発注に必要な機能（クロスセッションメッセージ、Lyria 3.5 API、ElevenLabs API/MCP）は、いずれも2026年9月時点で一般公開されている
